# 技能可见性新增 anonymous 档位

Status: accepted

技能作者需要自主选择技能面向“仅授权用户”“平台已登录用户”或“任何人（含匿名访客）”。现有 `private/public` 两档无法在保留登录要求的同时显式提供匿名安装能力，且各消费入口规则不一致：public 已发布技能可匿名搜索，但详情与远端安装要求登录。直接扩大 public 会在未经管理者选择时扩大既有技能的开放范围。

## 决策

- 逐技能可见性扩展为三档：`private`（仅授权用户，默认）、`public`（平台已登录用户）、`anonymous`（任何人，含匿名访客；已登录用户同样可消费）。
- `anonymous` 只开放已发布版本的消费面（发现、详情、下载、安装），不开放源码仓库、未发布内容或反馈协作权限。
- 现有技能升级后保持原档位；正常新建入口与数据库默认值对齐 `private`，不借默认值变更回写旧数据。
- Server 是授权事实源。匿名访问已知 `private/public` 身份、版本或包地址仍被拒绝；Web 与 CLI 不复制访问策略。
- 匿名搜索、详情与包下载只开放 `anonymous` 已发布技能。匿名显式筛选 `public/private` 返回需要登录的明确错误，而不是空结果。
- `anonymous` 技能全部仍可安装的已发布版本，其完整依赖链必须匿名可装。切换到 `anonymous` 与发布 `anonymous` 新版本时按已冻锁校验；不自动公开依赖。
- 依赖收紧前检查仍以 `anonymous` 发布的已发布反向依赖；存在冲突则阻止，并提示有权管理者处理。不自动修改依赖方档位。
- 收紧可见性只影响后续服务端访问；不实现远程撤回、删除或禁用已安装副本。选择 `anonymous` 时向管理者展示不可追回提示。

## 考虑过的方案

- **直接把 public 改成匿名可用**：无法区分“登录用户”和“任何人”，且会在管理者未选择时扩大既有技能的开放范围，拒绝。
- **新增“全组织可见”档位**：组织成员身份不等于技能读取授权，且与三档消费范围正交，拒绝。
- **客户端各自复制匿名判定**：会与 Server 授权规则分叉，拒绝。
- **自动把依赖提升为 anonymous 以满足链约束**：扩大依赖作者的开放范围，拒绝。

## 后果

- 作者可以主动提供无需账号的安装入口，同时保留需要登录的 public 档。
- 匿名安装承诺由 Server 在发布与档位切换时维护，客户端只呈现结果。
- Web 新增公开消费者目录与详情入口；管理后台、可见性修改、源码协作与反馈区继续受既有认证授权保护。
- CLI `search`/`info`/`install` 在没有登录态时只消费 anonymous 技能；public/private 的筛选与访问明确要求登录。
- 需要同步内置 `esl-operator` 技能、领域术语、命令帮助与测试，保持客户端与服务端契约一致。
