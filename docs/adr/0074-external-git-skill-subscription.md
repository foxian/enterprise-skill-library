# 外部 Git 技能引用与自动发布

Status: accepted

## 背景与取舍

允许将外部 Git 仓库中的技能引入 ESL 并持续跟踪上游，同时保持既有身份、访问治理和不可覆盖的 Skill Release 语义。选择命名空间内的受管引用与自动发版，而不是仅保留外链或同步未发布源码，以便消费者通过 ESL 正常安装并明确选择升级；内容维护权留在上游，ESL 内仅管理引用配置与访问边界。

## 已确认的来源与归属边界

- 第一版仅支持无需凭据即可读取的 HTTPS Git 仓库；以仓库地址、技能目录与跟踪分支定位单个技能，默认跟踪默认分支。可选择仓库根目录或子目录；不含私有仓库凭据接入或整仓多技能批量导入。
- 外部引用技能可归属于个人 Namespace 或组织 Namespace，不局限于组织。沿用既有命名空间身份与权限边界，不因支持外部来源扩大登记或管理权限。
- 明确展示上游地址与外部来源；上游作者不自动成为平台所有者。不同命名空间可分别引入同一上游技能；平台内的引用治理权不代表取得上游作品的著作权。

## 已确认的内容与消费边界

- 初次引入以及检测到有效内容更新后，自动形成新的可安装 ESL Skill Release，而不只更新未发布源码；这里不要求上游创建 GitHub Release。
- 保留既有 Release；新安装或显式升级消费新版本，不自动改动用户电脑上已安装的副本。版本编号、清单映射与安全校验见下文。
- 上游技能内容在平台内只读：禁止内部编辑、上传覆盖或手动发布。允许有权限者修改同步周期与可见性、立即同步、暂停同步及移除引用。只读是内容维护边界，不是取消管理能力。
- 上游仅被读取，不向上游推送。平台生成发布所需元数据，不修改上游仓库；字段映射见下文。

## 已确认的访问治理边界

- 完全复用平台访问治理，不新设外部技能专属的“组织私有”语义。private 仍表示仅授权用户，并不默认授予全部组织成员访问权；组织成员访问可通过既有团队授权实现。个人命名空间同样沿用现有授权边界。
- public 面向平台已登录用户，不默认解释为互联网匿名开放。匿名档位按 ADR-0073 的最终落地契约接入；本提案不视该档位为已经实现。
- 可见性与显式授权、Release 生命周期保持独立（ADR-0062）；自动同步或发版不得隐式改变公开范围。

## 已确认的调度与变化检测

- 采用日历计划：每天选择时间，每周选择星期几与时间，每月选择日期与时间；当月不存在该日期时，在当月最后一天执行。每项引用明确显示时区，默认使用平台配置时区。
- 服务停机恢复后，只补一次最近遗漏的检查，不逐次补跑。
- 选定技能目录内文件的新增、修改或删除触发内容更新；另行选定的目录外许可与署名文件是明确例外，其变化同样纳入检测与发布确认；仓库无关目录的提交不触发发版。检查记录上游提交标识，内容无变化不产生新版本。

## 已确认的失败与版本策略

- 上游不可访问、分支或目录被删除、技能校验失败时，保留最后一个成功版本，不自动删除或下架。展示失败原因、最近成功时间与下次检查时间；后续按计划重试，也允许手动重试。
- 初次引入失败时，保留可修正或移除的失败记录，不产生可安装版本。
- ESL 独立编号：首次成功为 0.1.0，每次成功发布内容更新递增 patch。上游提交标识单独记录；该序列不表示兼容性保证。
- 平台生成发布所需元数据，不要求修改上游仓库；清单字段与平台身份的映射见下文。

## 已确认的许可证边界

- 引入时展示检测到的许可证及其来源，由操作者确认可按所选范围分发。没有明确许可依据时阻止首次发布，不静默补入 MIT 或其他默认许可证。
- 后续检测到许可证变化或消失时，暂停自动发布，等待重新确认；保留上游许可与署名文件。引用目录之外的许可文件范围见下文。

## 已确认的交付入口

- 第一版在 Web 提供创建引用、查看状态、修改计划与可见性、立即同步、暂停同步及移除引用。
- CLI 暂不新增外部引用管理命令；沿用既有搜索、查看、安装与升级流程消费外部引用技能。

## 已确认的上游定位与身份连续性

- 首次成功发布后锁定仓库地址、技能目录和跟踪分支。默认分支在创建时解析为具体分支名；上游调整默认分支，不让已有引用自动切换目标。
- 更换来源应创建新引用，不接续原技能身份的版本历史。首次发布前允许修正填错的来源；同步计划与访问范围仍可独立管理。

## 已确认的暂停、归档与移除

- 暂停仅停止定时检查，已有版本仍可按权限安装；恢复同步恢复计划并检查一次，不自动恢复已归档技能。
- 归档停止同步，消费边界沿用既有归档规则；归档恢复后默认保持暂停，由有权限的管理者显式恢复同步。
- 移除引用先归档，再按 ADR-0040 的分级权限与确认流程删除整个技能，展示版本数量与受影响依赖方，不新增绕过既有删除权限的入口。
- 不支持解绑外部来源后转为内部可编辑技能；已经下载到本地的副本不被收回。

## 已确认的身份与清单映射

- 创建时确认目标 Namespace 与短名，短名可由上游建议；冲突要求修改，不覆盖已有技能。上游改名不自动改变 ESL 身份；简介随有效更新同步。
- 平台生成身份、版本和发布元数据，上游 SKILL.md 与资源保留原始字节。现有发布校验若依赖上游名称与平台身份一致，应适配外部来源发布路径，不以改写上游文件规避。
- 上游存在 release.json 时解析其中可用的许可证与描述元数据，身份与版本仍以平台配置为准。显式 ESL 依赖沿用既有发布校验；无法解析的依赖或冲突清单阻止发布，不静默丢弃。
- 不从自然语言中提及其他技能自动推断依赖。

## 已确认的目录外文件边界

- 默认仅纳入所选技能目录内资源；例外是适用的许可与署名文件。创建时展示所选目录及其祖先目录中的候选文件，由管理者确认适用文件，并保留原路径与来源记录。
- 选定的目录外许可或署名文件变化也纳入检查与重新确认，明确作为仅目录变化检测规则的例外。发布包附带这些文件，其变化计入制包内容变化；许可依据不明确时继续阻止发布。
- 不递归抓取其他目录、子模块或外部资源地址；第一版不承诺任意目录外依赖可用。引入预览提示该限制，由管理者确认。

## 已确认的安全抓取边界

- 只读取允许的公网 HTTPS 地址；禁止本机、私网、链路本地和云元数据目标，域名解析与每次重定向均重新检查。不向外部来源转发平台凭据。
- 抓取与制包不执行上游脚本或安装依赖；限制耗时、文件数与体积，超限给出可见错误。拒绝路径逃逸，不跟随越界符号链接。
- 不递归抓取子模块，不隐式下载 Git LFS 对象；发现所选目录需要这些机制时明确报不支持。
- 安全抓取校验不等于恶意内容审查或可信认证。

## 已确认的分发范围扩大

- 可见性变更沿用既有权限规则；从受限扩大到更公开范围时，重新展示适用许可证，要求管理者确认具备扩大分发的许可依据。收紧范围不要求重新确认许可。
- 公网仓库可读取不等于已获得再分发许可；自动同步不改变可见性，也不自动公开依赖。

## 对既有约定的影响与交付验证

- 本提案为内部协作维护的 Server-hosted Skill Source 增加外部引用只读来源类型，不改变普通内部技能的编辑与发布流程。外部来源使用受管自动发布路径，保留既有 Release 不可覆盖、权限与依赖校验边界。
- 独立生成发布元数据是对普通源码发布输入要求的显式扩展，不要求外部仓库预先含有 ESL release.json；制包保持 ADR-0068 的字节安全约定。
- 实施需覆盖命名空间权限、只读写入口拦截、日历与漏跑、手动和定时同步并发幂等、无变化不发版、失败保留旧版、许可确认、路径与网络安全、归档删除及搜索安装升级消费链路。
- 重试与并发不得重复发版或覆盖旧版本，失败不得污染最后成功版本；归档、暂停与删除的竞态需在实现中验证。
- 第一版无新增 CLI 管理命令；若实际实现改变 CLI 消费行为，同一变更须同步 skills/esl-operator/ 的 SKILL.md 与 references。实施按仓库约定执行 npm test 与 npm run build。

## 访谈状态

三轮逐项决策均已由用户确认，第三轮六项建议全部接受。当前没有尚待分支选择的产品问题；整体方案已由用户确认达成共同理解。文档现为 accepted；未开始功能实现，未创建规格工单，也未提交代码。整体确认不自动等同于授权开始实现或发布工单。
