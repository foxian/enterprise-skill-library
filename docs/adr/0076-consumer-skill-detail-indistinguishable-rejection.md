# 消费详情「不存在 / 无权 / 已归档」统一不可区分响应

- Status: accepted
- Date: 2026-11-23
- 本 ADR 由 #199（技能目录）引入，编号接当前 `docs/adr/` 最大编号 0075

## 背景

消费向技能详情同时服务免登录公开目录与登录后的技能目录。当前 `GET /api/skills/*` 对三种不可用状态给出不同响应：不存在返回 404，已登录但无权返回 403，匿名访问非 anonymous 技能返回 401；已归档技能甚至没有状态拦截，只要可读就继续返回内容。这会让任何能构造 URL 的主体把「技能存在 / 不存在 / 私有 / 已归档」区分出来，形成存在性泄露（#199 US16）。

技能目录把详情页暴露给更多登录用户，且列表与详情之间可能发生权限收紧或归档。必须先把消费详情的失败形态定死，否则后续每个入口都会各自补一套错误处理。

## 决策

1. **范围**：本决策约束消费向详情端点（`GET /api/skills/:scope/:skillName`，即公开目录与技能目录共用的详情读取），不约束管理向端点。管理向权限矩阵、管理页与归档恢复仍返回真实的 404 / 403 / 状态信息。
2. **已登录消费主体**：不存在、无权读取、已归档三种状态返回**完全相同的 HTTP 状态码与响应体**，统一为 `404` + `skillNotFound` 语义的通用错误；不得返回技能名称、`@scope/name`、描述、版本、下载量、可见性、归档状态或任何可用于区分的元数据。
3. **为什么是 404 而不是 403**：403 本身确认「资源存在但无权」；410 会确认「曾经存在、已归档」。404 是唯一不增加存在性信息的选择。客户端只据此展示统一的「无权访问或已下架」提示与返回出口。
4. **归档**：`skills.status = 'archived'` 在消费详情按不可用处理，与无权、不存在同形。Maintainer / 组织管理成员 / 平台管理员查看归档技能走既有管理向路径，不依赖消费详情。
5. **匿名主体**：按 #200 US14「匿名详情行为完全不变」，匿名访问已存在的、未归档的非 anonymous 技能仍返回 401 登录提示，不存在仍返回 404。本 ADR 的三态统一只覆盖已登录主体；匿名仍存在「存在但需登录」与「不存在」的区分，这是本次为保持公开目录体验而接受的残余风险，若未来要求严格匿名不可区分，另案收紧。匿名访问已归档技能返回 404（它已不可消费），不保留「需要登录」提示。
6. **服务端日志**：对外统一，对内仍记录真实的失败原因（not found / no read access / archived），便于排障；日志不进入响应。
7. **名称重定向**：既有 Skill Rename 的 301 重定向保持不变；它不属于本决策的三态范围。注意它对已重命名的私有技能同样暴露存在性，后续如需收紧应另立决策。

## 考虑过的方案

- **403 表示无权、404 表示不存在**：保留可行动错误，但直接泄露存在性，拒绝。
- **410 Gone 表示已归档**：语义清晰，但确认技能曾存在，拒绝。
- **所有状态统一 401**：会误导已登录用户去重新登录，且仍与「不存在」的 404 分叉，拒绝。
- **统一 403**：对不存在也返回 403，虽不可区分但暗示「存在且无权」，且与既有客户端约定冲突，拒绝。
- **前端把 403/404 都渲染成同一页、服务端保持可区分**：只挡住 UI，挡不住直接调 API，拒绝。
- **归档仍可只读展示、仅从目录隐藏**：会让「已下架」承诺失效，且权限收紧后用户仍能看内容，拒绝。

## 后果

- `SkillDetailView` 对已登录主体的 404 统一展示「无权访问或已下架」+ 上下文返回出口，不再区分具体原因。
- 服务端测试必须以「三种 fixture 的 status 与 body 完全相等」为断言，而不是只断言各自状态码。
- 管理向页面与 API 不受影响；维护者仍能通过管理入口查看归档技能。
- 客户端无法再据详情错误码做「申请权限」等差异化引导；既有「向 Maintainer 申请」文案只能作为统一提示的一部分，不能条件渲染。
- CLI `info` 也消费同一端点（`packages/cli/src/commands/info.ts:66-78`）：已登录用户读取无权 private 技能时不再收到 403 的可行动指引，而是与不存在相同的通用 404。这是不泄露存在性的直接代价；CLI 不应在本端重新区分。
- 既有断言详情 403 的服务端测试（如 `packages/server/tests/public-visibility.test.ts:139-147`、`packages/server/tests/org-skill-authority.test.ts:83-92`）必须随契约更新为「三态响应完全相等」，不能保留与新契约矛盾的断言。
- 匿名登录提示保留，存在性泄露的残余风险需在后续决策中显式复核。
