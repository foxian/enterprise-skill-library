# 技能目录漏斗事件的最小载荷与来源字段模型

- Status: accepted
- Date: 2026-11-23
- 本 ADR 由 #199（技能目录）引入，编号接当前 `docs/adr/` 最大编号 0075

## 背景

技能目录 V1 需要建立「访问目录 → 查看详情 → 复制安装命令」三层漏斗基线，当前平台没有任何 Web 行为埋点。最省事的做法是把能拿到的字段都存下来（搜索关键词、IP、客户端环境、用户 id、时间戳），或者复用下载日志表；但这些选择会带来不可逆的隐私面、口径混淆与信任问题。字段模型一旦开始采集，就无法「未采集」。

## 决策

1. **独立存储**：新增 `catalog_funnel_events` 表，不复用 `download_logs`。二者语义、可见面与保留策略不同；下载日志是「包发放」事件且含 Super Administrator 明细，漏斗事件是「页面行为」原始流。
2. **最小载荷**（与 #200 的事件契约一致）：
   - `subject_user_id` / `subject_username`：请求时服务端从登录态解析；匿名或无法解析为 `NULL`。
   - `skill_id`：`detail_view` 与 `install_command_copy` 必填，`catalog_view` 为空。
   - `action`：仅 `catalog_view | detail_view | install_command_copy`。
   - `bucket`：仅 `all | platform | org | granted`，且只在 `traffic_source = skill_catalog` 时有值，其他来源为 `NULL`。
   - `traffic_source`：`skill_catalog | public_catalog | direct_or_unknown`；缺失或非法一律落 `direct_or_unknown`。
   - `occurred_at`：服务端 UTC 时间，不信任客户端。
3. **不采集**：搜索关键词原文、IP（含截断网段）、User-Agent、客户端环境、设备指纹、页面停留时长、滚动位置。关键词不落库是产品与隐私的共同决定；需要关键词分析时另开需求，不要在事件表里「顺手」加列。
4. **不做去重**：事件是原始动作流，不去重、不计算 UV。相同主体重复访问目录就是多行。UV、转化率、漏斗比率属于报表层口径，基线期后再定；原始行保留才能重算。
5. **来源标记不参与授权**：`traffic_source` 由目录跳转链接的 query 承载，可被伪造。它最多影响分析归属，**不得参与任何权限判定**。无标记或标记无效记 `direct_or_unknown`。
6. **漏斗口径**：V1 只统计 `traffic_source = 'skill_catalog'` 的事件作为本漏斗；公开目录与直拼流量照常入库，不混入本漏斗。不建统计 UI，由研发按需/按约定周期导出。
7. **保留期**：V1 不删除原始事件。若未来需要保留期，参照 ADR-0067 的「明细过期、聚合保留」另做决定；不要提前写清理任务。
8. **上报鉴权**：`POST /api/catalog/events` 允许匿名调用（公开目录流量需要入库），登录态可选；服务端补主体与时间，忽略客户端传来的 `subject_user_id` / `occurred_at`。伪造来源或动作不可能绕过任何权限检查。
9. **不外键 `skill_id`**：技能可能被删除或改名，事件必须保留；`skill_id` 只是分析键，不构成引用完整性约束。

## 考虑过的方案

- **复用 `download_logs`**：表义不同，下载日志 90 天删除明细、仅超管可查，混入页面行为会污染两套口径，拒绝。
- **只存聚合计数**：无法事后重算漏斗、无法按来源拆分、无法审计异常，拒绝。
- **存搜索关键词**：spec 明确不记录，且关键词可能含用户输入的个人/业务信息，拒绝。
- **存 IP / User-Agent 以支持来源分析**：超出「三层动作计数」的最小必要范围，且与 ADR-0067 的隐私取向冲突，拒绝。
- **客户端传 `occurred_at`**：时钟不可信、可伪造，拒绝。
- **按 session 去重后再入库**：失去原始流且去重规则会变，拒绝；去重留在报表层。
- **事件端点强制登录**：公开目录的匿名流量将无法入库，与 #200 的来源模型冲突，拒绝。

## 后果

- 新增表、Repository、路由与迁移；`databaseSchema` 追加建表即可，旧库启动时自动补齐。
- 事件表不含外键，技能删除/改名后仍保留历史；报表按 `skill_id` 与时间聚合。
- 上报端点公开可调用，V1 无防刷；基线期接受虚高风险，后续可在网关/路由限流，但不得用去重掩盖刷量。
- 匿名事件 `subject_user_id` 为空，报表需区分「匿名」与「主体缺失」；ESL 原生 token 可能没有数值 id，按 `subject_username` 兜底。
- 测试需断言：最小载荷落库、缺失/非法来源归 `direct_or_unknown`、伪造来源不改权限、漏斗查询只取 `skill_catalog`。
