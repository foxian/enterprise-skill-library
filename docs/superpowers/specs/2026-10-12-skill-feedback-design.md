# 技能反馈第一版设计

日期：2026-10-12

状态：产品规则与规格已确认；中等优先级，暂缓实施，尚未排期。研发任务：[Issue #130](https://github.com/foxian/enterprise-skill-library/issues/130)。架构决定见 [ADR-0066](../../adr/0066-skill-feedback-reuses-gitea-issues.md)。

## 目标与架构

Skill User 在使用技能时提交问题或改进建议；有权使用同一技能的用户共同讨论，技能管理者查看、回复并处理，用户可查询结果及解决版本。

复用技能对应 Gitea 仓库的 Issue 保存反馈正文、评论和打开／关闭状态。ESL 提供 CLI、Agent 与 Web 入口并执行授权，不要求用户操作 Gitea UI，不将技能反馈默认提交到 ESL 产品研发 GitHub 仓库，也不另建一套完整正文与评论存储。

## 范围

支持当前实例中有对应仓库的技能，包括未发布技能。纯本地技能和内置技能暂不支持在线反馈。从本地安装记录发起时，需要明确定位原服务端和技能；无法定位时返回可行动提示，不猜测实例或误投当前配置的其他实例。

第一版不包含附件、逐条私有反馈、投票、邮件通知、跨技能收件箱、外部任务系统同步、自动发布关闭或额外强制处理状态。

## 授权

所有反馈请求均要求登录，服务端按当前技能权限校验，包括 public 技能。不得仅通过 UI 隐藏操作实施授权。

| 操作 | 要求 |
| --- | --- |
| 查看列表、详情及评论 | 当前技能 Read 或更高权限 |
| 提交反馈、添加评论 | 当前技能 Read 或更高权限，且技能未归档 |
| 编辑反馈标题／正文及评论 | 当前技能 Read 或更高权限、当前用户为相应内容作者，且技能未归档 |
| 分类、指派、关闭、重新打开 | 当前技能 Manage 权限；归档例外见生命周期规则 |
| 使用者自行删除整条反馈 | 第一版不提供 |

Write 权限不额外授予反馈管理权。用户失去 private 技能访问权后，也失去自己历史反馈的访问权。已有提交者身份不是持续访问授权。

反馈随技能当前访问范围变化。提交时展示“反馈对有权访问该技能的用户可见”；private 改为 public 的操作确认需要提示历史反馈也将扩大可见范围，管理者可取消操作并先检查内容。

## 反馈内容

- 标题、描述必填，描述支持 Markdown；类型为“问题”或“改进建议”。
- 使用版本可选。从已安装技能发起时读取可识别的安装版本；无法识别时允许留空。版本表示发生问题时使用的版本，不能悄悄替换为最新版本。
- 保留真实提交者、评论作者、创建和更新时间；用户可编辑自己的内容，不获得分类等管理字段编辑权。
- 管理者可指派负责人；候选身份与所需权限的具体映射须在实现中验证，不默认把所有 Gitea 用户作为可指派对象。
- 展示原生 Issue 的打开／关闭状态，反馈编号限定在所属技能仓库内；同号反馈不能跨技能解析。
- Markdown 渲染遵守现有 Web 内容安全规则，不直接信任用户输入的 HTML。

## 用户流程

1. 用户在 AI 工具里提出反馈意图，Agent 确定目标技能、实例及可识别的使用版本。
2. Agent 整理标题、描述和类型，将最终内容展示给用户，并说明共同可见范围。
3. 用户确认后，Agent 调用 ESL CLI 提交；不自动上传完整对话或项目文件。
4. 成功后返回反馈编号和可用的 ESL 查询方式；未知是否成功的上游超时不能宣称提交成功，也不能盲目重试导致重复提交。
5. 使用者通过 CLI 查询、评论和编辑自己的内容；Web 支持列表、详情、回复和具备权限时的管理操作。

CLI 非交互显式调用是脚本操作，不应重复要求 Agent 对话确认；Agent 的提交前确认由客户端耦合的操作员技能约束。缺少必要用户决策时复用现有 Agent Interaction Request，不新增另一种协议。

## CLI 契约范围

不增加顶层快捷命令，资源路径为：

```text
esl skill feedback create <skill-identity>
esl skill feedback list <skill-identity>
esl skill feedback view <skill-identity> <number>
esl skill feedback comment <skill-identity> <number>
esl skill feedback edit <skill-identity> <number>
```

上述路径表达已确认的命令范围；具体 flags、评论编辑定位方式和请求 DTO 在实现阶段确定。每次指定技能，view/comment/edit 另指定该技能内编号。create 支持标题、描述、类型及可选版本；list 支持打开／关闭筛选与分页；view 展示正文、讨论和处理结果；comment 添加评论；edit 修改本人反馈或评论。

命令支持结构化 JSON 输出、完整非交互参数和既有 Agent Interaction 协议。可复用的身份与反馈契约逻辑放在 `packages/core`，CLI 解析、输出与退出行为放在 `packages/cli`；服务端集成与授权保留在 `packages/server`。同步修改 `skills/esl-operator/SKILL.md` 及相关 references、CLI 使用文档与帮助。

## 管理端及处理规则

技能页面提供反馈列表，支持打开／关闭筛选和分页；详情显示类型、作者、使用版本、正文、评论、负责人及解决结果。按用户权限呈现操作，但所有变更仍由服务端校验。

管理者通过 Web 分类、指派、关闭及重新打开反馈。沿用 Gitea 打开／关闭状态，不引入已计划／处理中等强制状态。

关闭必须注明原因：已解决、重复、暂不采纳或无需处理。已解决必须填写解决说明；通过发布修复时可关联解决版本；仅源码修改时明确“源码已修改，尚未发布”。不以关闭等同于已解决，不随发布自动关闭反馈。历史处理说明应可查询，具体映射不得因重新打开而丢失讨论内容。

第一版用户通过 CLI 或 Web 主动查询处理结果，不发送邮件通知。

## 生命周期

| 技能状态或操作 | 反馈行为 |
| --- | --- |
| 活跃、已发布或未发布 | 按权限正常操作 |
| 归档 | 按权限查看；停止新增、评论和编辑；Manage 用户仍可关闭已有反馈；其他管理修改须先恢复技能 |
| 恢复 | 恢复正常反馈操作 |
| 彻底删除 | 随仓库删除反馈；技能删除确认页提示此后果，不另建反馈历史备份 |
| 删除后同名重建 | 使用新 Skill ID 和新仓库，不继承旧反馈 |

删除流程继续遵守 ADR-0040 的分级权限与失败恢复规则，不因新增反馈改变其删除授权。

## 集成验证与实现风险

以下尚未通过当前部署的 Gitea API 验证，不应视为已有能力：

1. 创建、查询、评论、编辑、标签、指派和状态修改的 API 及分页行为；技能仓库 Issue 单元是否已启用，历史仓库如何启用。
2. 用户令牌或代理调用能否保留真实提交者与评论作者；不能静默把服务账号显示为全部内容的作者。
3. 当前团队授权已包含 `repo.issues`，Issue 原生权限与 ESL Read/Write/Manage 规则不保证等价。须核对 Git Backend 的可达路径和用户凭据能否绕过 ESL，包括作者原生关闭权限、Write 的管理权限、匿名读取 public 仓库，以及归档后操作。
4. 私有仓库向 public 切换后的历史反馈访问范围，以及登录要求能否在所有对外 Issue 路径上成立。
5. 分类、使用版本、关闭原因、解决说明及解决版本如何映射。优先使用原生字段／标签／处理评论；确需补充元数据时，仅保存必要结构化字段，不复制完整正文与评论，不依赖解析可随意编辑的正文维持授权或关键状态。
6. 原生 Issue 与 Pull Request 共用编号的情况：反馈列表和详情应只处理 Issue，不能将 PR 当成反馈或允许跨仓库编号越权。
7. 后端中断、部分成功、重复提交与状态变更的错误呈现和恢复。失败时不得虚构成功结果或把私有上游信息泄漏给未授权用户。

若验证发现原生 Gitea 权限无法满足已确认的共同可见及管理边界，应先提出具体冲突和可行修订，不静默降低授权标准或改为自建完整反馈系统。

## 验收条件

- 已登录、有当前技能 Read 权限的用户能对已发布及未发布技能提交、查询和评论，并只能编辑自己相应内容。
- 匿名、无权限、已撤权用户无法读取或修改反馈；Write 用户无法仅因 Write 获得管理操作；两个技能内同号反馈不能混淆。
- Manage 用户能分类、指派、关闭和重新打开；关闭原因和解决说明规则生效，使用者能查询结果及解决版本。
- Agent 提交前确认整理内容；非交互和 Agent Interaction 输出符合既有 CLI 契约；本地来源明确指向原实例，不支持的技能类型返回明确提示。
- private 改为 public 显示历史反馈可见范围提示；归档、恢复、彻底删除和同名重建符合生命周期表。
- 上游调用保留作者身份，过滤 PR，正确处理分页及失败；对外路径不能绕过约定的权限。
- CLI 帮助、文档、内置操作员技能和中英界面同步；按仓库规范运行 `npm test` 与 `npm run build`，并补充 Gitea 集成冒烟验证。

## 交付状态

当前只完成设计讨论和文档整理，没有增加 CLI、API、Web、数据库或 Gitea 行为。规格已发布为 [Issue #130](https://github.com/foxian/enterprise-skill-library/issues/130)，标记中等优先级并暂缓实施；`ready-for-agent` 仅表示规格就绪，不代表立即开发。后续实施以该规格为依据，技能使用反馈仍归属于对应 Gitea 仓库。
