# 可恢复跨系统开通实施计划

## 目标

将组织注册、成员生命周期、组织删除以及技能相关跨系统变更统一为可恢复的最终一致性工作流，并让账号与密码规则在 ESL 与 Gitea 之间保持一致。

## 实施批次

1. **账号与密码策略**
   - 在 `@esl/core` 提供组织成员名、Gitea 用户名和密码校验。
   - 服务端从部署参数读取共享密码最小长度。
   - 注册、成员创建、密码修改和管理员密码修改复用该策略。
2. **Operation 基础设施**
   - 增加持久化 Operation、租约、幂等键和审计表。
   - 实现条件领取、指数退避、脱敏错误和手工重试。
   - 保持纯 SQLite 变更使用本地事务。
3. **组织开通**
   - 申请先落库并返回 `provisioning`。
   - 进程内执行器按幂等步骤创建组织、管理员、Owner 关系和默认团队。
   - 成功后才转为 `active`，失败进入 `failed`。
4. **成员与删除**
   - 成员创建、禁用、启用、改密接入 Operation。
   - 组织删除先进入 `deleting`，Git Backend 成功后再清理本地技能，失败进入 `delete_failed`。
5. **状态访问控制与 Web**
   - 只有 `active` 组织允许登录、上传、发布、权限和成员管理。
   - Web 展示 provisioning、failed、deleting 和 delete_failed 状态以及可重试操作。
6. **技能与权限**
   - 技能创建、权限同步、发布通过 Operation 执行。
   - 保留 ADR-0011 的幂等续传和孤儿仓库补偿。

## 验证

每个批次先添加失败测试，再实现最小行为；批次完成后运行聚焦测试。全部完成后运行 `npm test`、`npm run build` 和 `git diff --check`，并进行代码审查。
