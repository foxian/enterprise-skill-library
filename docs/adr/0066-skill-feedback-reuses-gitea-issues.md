# 技能反馈复用 Gitea Issue 并面向技能使用者共同讨论

- Status: Accepted
- Date: 2026-10-12

## 决策

技能反馈采用同一技能当前有权使用的用户共同可见、共同讨论的模式，复用该技能对应 Git Backend 仓库中的 Gitea Issue 承载反馈正文、评论和打开／关闭状态。ESL 不另建一套保存相同正文与评论的反馈工单系统，也不将这些技能反馈默认提交到 ESL 产品的 GitHub 研发仓库。

用户通过 ESL 的产品入口提交和处理反馈；Gitea 仍作为内部后端，Gitea UI 不成为正常产品入口，延续 ADR-0002 的职责边界。ESL API 按技能权限控制操作；共同可见不等于公开到互联网。

## 理由与取舍

技能已有对应仓库，共同讨论与 Gitea Issue 的仓库归属和讨论模型匹配，复用现有能力可减少自建评论、工单基础设施及两套内容同步的维护成本。代价是接受 Gitea Issue 的数据模型与生命周期约束，并需要核对其 API、作者身份和仓库权限映射。

不采用逐条私有反馈模型：本轮已选择技能使用者共同讨论；若未来需要提交者与管理者之间的私有沟通，应重新评估数据与授权边界。

## 已确定的入口与权限

- 用户可在 AI 工具对话中表达反馈，由 Agent 整理并调用 ESL CLI；CLI 支持提交、列表、查看和回复。Web 提供技能内反馈列表与查看、回复及管理处理入口。实现 CLI 契约时同步更新客户端耦合的内置 `esl-operator` 技能。
- 第一版所有反馈操作要求登录，每次请求按当前技能访问权校验；public 技能也不提供匿名反馈操作。用户失去 private 技能访问权后，不能继续查看自己曾提交的反馈。
- 当前具备 Read 或更高技能权限的 Skill User 可查看、提交及评论，并修改自己的标题、正文及评论。
- 关闭、重新打开、分类与指派负责人要求技能 Manage 权限；Write 本身不增加反馈管理权限。第一版不开放使用者自行删除整条反馈。
- 上述权限是 ESL 产品契约；实现前必须核对直接访问 Git Backend 的权限，避免底层原生操作绕过 ESL 限制。

## 已确定的内容与处理规则

- 标题和描述必填，类型为“问题”或“改进建议”，使用版本可选。从已安装技能发起时自动读取可识别的版本；无法识别时允许留空。第一版支持 Markdown 文本，不支持附件。
- Agent 提交前向用户展示整理后的内容，得到确认后提交；不自动上传完整对话或项目文件。
- 沿用 Gitea Issue 的打开／关闭状态；关闭时注明原因：已解决、重复、暂不采纳或无需处理。“已解决”必须填写解决说明；通过发布修复时可关联解决版本，源码已修改但尚未发布时应明确说明。发布不自动关闭反馈，第一版不增加已计划／处理中等强制状态。
- 反馈随技能当前访问范围变化，不另设逐条可见性。提交时提示内容对有权访问该技能的用户可见；技能从 private 切换为 public 前提示历史反馈也会扩大可见范围，由管理者检查内容后决定是否继续。
- 第一版通过 CLI 与 Web 反馈页面查询回复、状态及解决版本，管理者在技能管理页按打开／关闭筛选；暂不增加邮件通知、跨技能反馈收件箱或投票。

## 已确定的技能范围、生命周期与命令

- 支持当前 ESL Server 上有对应仓库的技能，包括未发布技能；纯本地技能和内置技能暂不支持在线反馈。从本地安装记录发起时须明确定位原服务端和技能，不得误投其他实例。
- 技能归档后保留反馈并允许有权用户查看，禁止新增、评论及编辑；Manage 用户仍可关闭已有反馈。恢复技能后恢复正常反馈操作。
- 彻底删除技能时反馈随 Gitea 仓库删除，删除确认页提示该后果；第一版不另建反馈历史备份，同名重建技能不继承旧反馈。
- CLI 使用 `esl skill feedback create|list|view|comment|edit`，不增加顶层快捷入口。每次明确指定技能；查看、回复与编辑再指定该技能内反馈编号。分类、指派、关闭及重新打开只通过 Web 提供。
- CLI 支持 JSON 输出、非交互参数和现有 Agent Interaction 协议，与内置 `esl-operator` 同步交付。

## 后续设计与验证

产品规则已完成逐轮确认，第一版规格见 `docs/superpowers/specs/2026-10-12-skill-feedback-design.md`。API 形状与 Gitea 元数据映射属于后续实现设计，必须满足本 ADR 的产品规则。

实现前需验证当前 Gitea 版本的 Issue API、提交作者归属，以及直接访问 Git Backend 时的权限是否会绕过 ESL 的预期限制。当前仅完成设计记录，尚未实现反馈功能。
