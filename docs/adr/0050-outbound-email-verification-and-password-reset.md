# 出站邮件、注册邮箱验证与密码重置

Status: accepted

用户邮箱已成为必填联系属性与 Git 匹配键（ADR-0046），但平台仍无出站邮件能力，
开放注册无法证明邮箱归属，忘记密码也只能依赖超管介入。我们引入出站邮件为一等
平台能力，并在其上提供可配置的注册邮箱验证与 Skill User 密码重置；同时明确它们
与既有 `registration_mode`、用户建号、用户禁用的边界。

## 决策

- **出站邮件**是 ESL Server 自管的事务性投递能力（邮箱验证、密码重置等），不经 Git Backend
  mailer。Super Administrator 配置 SMTP 投递参数与平台发件地址（From）；SMTP 凭据与 From
  分开配置。未正确配置时，依赖它的策略不得开启或须给出可行动错误。
- **注册邮箱验证策略**为独立平台设置，出厂默认关闭。仅当 `registration_mode=open`
  时生效：开启后，自助注册先进入邮箱验证待验（只占用用户名与邮箱，不创建 Skill
  User），点链接成功后才建号可登录。`approval` 模式忽略该策略（人审已覆盖准入）。
- **邮箱验证**还约束 Skill User 本人的用户邮箱变更：新邮箱验证成功前旧邮箱仍有效，
  待验新邮箱占用全局唯一池。用户建号与超管改邮不要求邮箱验证。
- **密码重置**仅面向 Skill User：用用户名发起、向当前用户邮箱发一次性链接；防枚举
  响应；合格用户邮箱才可自助重置，邮箱待补全则指向超管；禁用账号不可重置；成功后
  失效全部登录态并清除未兑现的建号首登改密要求。超管账号不走此通道。
- 邮箱验证待验、改邮待验与密码重置链接均过期；过期释放占用，重发作废旧链接。

## 考虑过的方案

- **邮验做成硬激活且与 approval 叠加 / 或第三种 registration_mode**：与现有准入模型
  叠床架屋；改为正交设置且 approval 时忽略。
- **待验即创建半残账号（禁登或仅验证页）**：Gitea/命名空间回滚成本高；改为与待审同构
  的申请占用，验证成功后再建号。
- **改邮未验证就切换并禁登**：易锁死用户；改为旧邮有效至新邮验证成功。
- **不做邮件、改由外部发信或软标记**：无法支撑硬门闩邮验与自助重置；接受出站邮件为
  平台依赖。
- **复用 Gitea mailer / From 绑死超管或 SMTP 用户名**：把产品事务邮件耦到 Backend 实现，
  或无法适配企业邮常见的服务账号+noreply From；改为 ESL 自管且凭据与 From 分离。
- **密码重置支持超管 / 用邮箱定位账号 / 禁用仍可重置**：扩大接管面或滑向邮箱登录；
  拒绝。

## 后果

- Super 控制台需配置出站邮件，并管理注册邮箱验证策略开关（与 `registration_mode`
  并列展示，approval 下说明邮验不生效）。
- 用户注册、本人改邮、忘记密码的 Web 流依赖可投递邮件；开发环境需提供可测的邮件配置
  或等价替身。
- 词表新增出站邮件、邮箱验证、注册邮箱验证策略、邮箱验证待验、密码重置；与 ADR-0046
  的用户邮箱/待补全/建号模型兼容，不引入「邮箱登录」。
