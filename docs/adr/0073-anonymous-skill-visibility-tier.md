# 技能可见性新增匿名访客档位

Status: proposed

## 已确认的决策

保留现有两档技能可见性，并新增第三档“任何人（含未登录访客）”，允许匿名访客安装该档位的已发布技能；不通过直接扩大现有 public 档位来替代第三档。

访谈中将未登录访问者称为“匿名访客”，与平台用户、组织成员区分。现有 private 档位仍表示仅有权限者可见，不表示组织所有成员默认可见。

## 已确认的匿名发现边界

匿名访客仅可搜索、查看第三档“任何人（含未登录访客）”的技能。仅授权用户可见的技能，以及要求平台登录才能使用的技能，均不向匿名访客公开，不能出现在匿名搜索与浏览结果中，也不能通过已知技能地址读取其详情。

结合已确认的第三档可匿名安装语义，匿名访客的发现、详情与安装应使用一致的可见性边界。现有 public 可被匿名搜索的行为需要收紧，以符合保留两档并新增第三档的决定；不能将现有 public 技能自动视为第三档。

## 已确认的匿名消费与收回边界

- 第三档向匿名访客开放技能介绍、已发布版本信息与安装包；不额外开放源码仓库、未发布内容或反馈区。安装包内原本包含的文件仍可随包下载。
- 网页提供第三档技能的匿名浏览入口；CLI 的 esl search、esl info 与 esl install 支持无需登录完成第三档技能的发现、查看与安装。网页与 CLI 使用同一访问边界。
- 技能从第三档改回受限档位后，立即停止后续匿名查看与下载，不尝试收回已经下载或安装到本地的副本。选择第三档时明确提示已分发文件无法追回。

## 已确认的三档命名与迁移

- `private`：仅授权用户；保留原有角色权限与显式授权规则，不表示组织所有成员默认可读。
- `public`：平台已登录用户；不向匿名访客开放搜索、详情与安装。
- `anonymous`：任何人（含匿名访客）；已登录用户同样可消费。
- 界面使用完整中文名称，不仅展示容易混淆的 public/private 字样。既有技能保持原档位，不自动升级为 anonymous；现有 public 的匿名搜索行为随本次变更收紧。
- 新技能继续默认 private；沿用现有可见性变更权限，不新增角色或扩大切换权限。可见性独立于 Release 发布，切换不增删显式授权。

## 已确认的依赖可见性约束

延续 ADR-0056 的消费者必须读得到整条依赖链原则：anonymous 技能的完整发布依赖链必须均为匿名可安装。

- 切换到 anonymous 时，校验仍可安装的已发布版本及其完整依赖链；存在受限依赖则阻止切换并提示冲突。
- anonymous 技能发布新版本时，存在受限依赖则阻止发布。
- 依赖技能收紧可见性前，检查仍面向匿名访客的已发布依赖方；存在冲突则阻止变更，由管理者先处理。
- 不自动公开依赖，不静默改变依赖方档位；消费端仍按当前权限检查完整依赖链，不因根技能匿名开放而绕过依赖权限。

## 对既有约定的影响与交付要求

本提案将 ADR-0049 中“匿名可发现 public 已发布技能”调整为仅 anonymous 可匿名发现；将 ADR-0062 的两档可见性扩展为三档，同时保留可见性与显式授权、发布生命周期解耦。ADR-0056 的依赖可读原则扩展到新增档位，不改变依赖版本策略。

实施应同步 Server、Web、CLI 的三档契约及内置 skills/esl-operator/ 的 SKILL.md 与相关 references，覆盖匿名与已登录用户的搜索、详情、下载、安装、可见性切换和依赖冲突测试，并运行 npm test 与 npm run build。
