# Source Upload 权限失败时不接管已托管源

Status: accepted

本地登录态是全局单槽位：同一台机器上「重新登录」就是用另一个 `<org>_<username>`
Skill User 的凭据覆盖本地槽位。各组织账号相互独立、互不关联（ADR-0016 单组织
归属、ADR-0020 登录面契约），同一自然人完全可能先后登录不同组织的账号。而 Git
Backend 对「无权限的仓库」与「不存在的仓库」返回相同错误（404/not found），客户端
无法区分。现状 `esl upload` 在已托管目录（存在 `esl` remote）上 fetch 失败且错误
疑似 not found 时，会进入 orphan 处理分支，交互提示删除 remote 并以当前账号重新
注册——在切换过登录的机器上，这等于把其他账号维护的 Server-hosted Skill Source
交互式接管成自己的新源，是一次跨用户资产劫持。我们决定：**orphan 重新注册不由
upload 的鉴权失败自动触发**。

具体决策如下：

- **鉴权失败一律不自动接管**：已托管目录的 fetch/push 失败一律按「凭据不足或源
  不可达」处理，报可行动错误——提示该源可能由其他账号/组织维护，指引「用维护它的
  账号重新登录后再 `esl upload`」；不再交互式引导删除 remote。该阻断不依赖对
  「归属」的精确判定：客户端无法从 404 区分无权限与不存在，故按保守方向处理。
- **orphan 重新注册只保留显式手动路径**：用户自行 `git remote remove esl` 后重新
  执行 `esl upload`（两步显式操作即为确认接管）。CLI 不提供单步接管入口。
- **已安装副本不受切换影响**：已安装技能的本地消费链（adapt、list、运行）与登录态
  无关，切换登录后照常离线可用；这保证「切换登录」永远不破坏本地使用，只影响服务
  器侧刷新操作。

## Considered Options

- **`--adopt` 显式旗标**：仍把「接管他人源」做成产品功能入口，与「各组织账号相互
  独立、互不关联」的账号模型相悖；手动两步已足够表达显式确认。放弃。
- **维持现状（交互式 orphan 引导）**：把权限失败误判为孤儿，构成跨用户泄漏路径。
  放弃。
- **记住每个目录上次成功 push 的账号以精确判定归属**：需新增本地状态，且目录可被
  移动/复制，状态不可靠；且仍无法消除 404 歧义。放弃。

## Consequences

- `esl upload` 在异账号场景下从「交互式重新注册」变为「硬报错 + 切回原账号指引」；
  orphan 分支仅剩用户显式移除 remote 的手动路径。
- 真孤儿（仓库确已从服务器删除）的恢复路径变长：需手动 `git remote remove esl`
  后重新 upload。
- 配套的普通 CLI 行为变更（不在本 ADR 范围，另行实现）：新增 `esl logout` 显式
  清除本地凭据；`update`/`install` 对 private 技能失败时给出可行动错误（提示技能
  归属的账号/组织，指引切回对应登录），替代现状的裸 403 信息。
